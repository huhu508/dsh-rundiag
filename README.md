# rundiag

把训练计划、完成情况和 COROS 数据放进同一张时间轴。rundiag 是 DSH 的右侧栏插件，用任务、复盘和教练指标回答一个问题：**今天该练什么，练完之后身体怎么样。**

> 显示名 `rundiag` · npm/仓库名 `dsh-rundiag` · 当前版本 `0.6.0`
>
> 0.6.0 界面刷新：输入框上移、模式图标、完成度圆环、单行类型选择、更紧凑的空白态与更清晰的卡片层级。

## 为什么是 rundiag

大多数任务应用只记录“做没做”，大多数运动应用只记录“练了什么”。rundiag 把两者放在同一天里：

- 左边是计划：今天想跑 8 km，或者只是一次轻松恢复；
- 右边是事实：COROS 记录到的距离、心率、负荷和恢复数据；
- 中间是复盘：主观疲劳、数据疲劳、短期/长期负荷和下一堂训练建议。

它不替代教练，也不假装拥有 COROS 的私有算法。它把公开的运动科学指标、你的训练记录和每日感受放在一个可解释的界面里。

## 功能一览

| 模块 | 能做什么 |
| --- | --- |
| 日期计划 | 按周浏览过去和未来的每一天；任务落在具体日期，不再只有“今天/未来”两个抽屉 |
| 任务与子任务 | 标题、描述、开始/截止日期、优先级、标签、类型；子任务独立完成，父任务自动汇总 |
| 快速添加 | 输入 `晨跑 8km 明天 #训练 !高`，自动解析日期、标签和优先级 |
| 完成度 | 勾选完成，或按次数、距离、时长累计目标；父任务显示子任务进度 |
| 能量球 | 计划球与实际球都是透明水晶球；拖动有惯性、碰撞和拉伸形变，可融合成绿色完成球 |
| 每日复盘 | 主观疲劳、睡眠、酸痛、心情、训练评分、训练备注、训练日记，自动附带负荷快照和教练建议 |
| 教练视图 | 训练准备度、CTL/ATL/TSB、ACWR、单调性、strain、HRV、静息心率、VO₂max、阈值、成绩预测 |
| COROS 同步 | 邮箱/手机号/Token 登录；同步最近 30 天活动和最近 120 天每日指标；自动汇总今日训练 |
| 数据安全 | 增量操作、写入前备份、完整 JSON 导出；token 只保存在 Host 端，不返回浏览器 |
| 兼容性 | DSH 0.2.2 的 `connection` 鉴权与 DSH 0.2.3-alpha 的 `webServer` peer 鉴权 |

## 安装

从 GitHub 安装：

```sh
dsh plugin add github:huhu508/dsh-rundiag
```

也可以：

- 在 DSH 插件安装入口填入 `github:huhu508/dsh-rundiag`；
- 下载 [v0.6.0 Release](https://github.com/huhu508/dsh-rundiag/releases/tag/v0.6.0) 中的 `dsh-rundiag-0.6.0.tgz` 安装；
- 本仓库源码目录通过 `plugin_manager install_bundle <绝对路径>` 安装（开发时使用）。

安装或更新后**刷新一次 DSH 页面**，让 Client 插件重新加载。

### 环境要求

- DSH Desktop / Web，能打开右侧栏；
- 能访问 `teamcnapi.coros.com`、`teamapi.coros.com` 或 `teameuapi.coros.com`；
- 一个 COROS 账号。没有 COROS 也可以把它当作普通日期任务与复盘工具。

## 快速开始

1. 打开任意会话的右侧栏，在指南页选择 `rundiag`。
2. 进入 `同步`，选择区域，用邮箱、手机号或 access token 连接 COROS。
3. 回到 `计划`，选一个日期，输入任务；先点类型（训练/学习/工作/生活/创作/其他），再提交。
4. 完成计划后勾选任务，或者让 COROS 同步到当天活动。
5. 把实际球拖到同一类型的计划球上，融合成绿色球。
6. 打开 `复盘`，记录感受；在 `教练` 查看负荷、恢复和下一堂训练建议。

## 界面

### 计划

- 顶部日期条按周切换；箭头翻周，点击周标题或 `今天` 回到今天。
- 输入框在能量球上方，选好类型后直接提交；模式标签带图标。
- 每个日期只显示当天的根任务；已完成任务不再占据任务列表，完成状态由能量球表达。
- 右上角的 `准备度` 来自教练引擎，不是手填值。
- 快捷键：`N` 聚焦输入框，`R` 刷新数据，`Esc` 关闭详情。

### 能量球

- **计划球**：添加任务后生成，虚线/空心质感，颜色代表任务类型。
- **实际球**：手动完成或 COROS 识别到当天活动后生成，实心/液体质感。
- **绿色球**：两颗球融合后的完成态。
- 球上没有文字标签；类型用颜色区分，计划/实际用填充方式区分。
- 球包含完整训练属性：距离、时长、平均/最大心率、卡路里、训练负荷、爬升、平均/标准化功率、运动类型、活动 ID。
- COROS 生成的球不能删除、不能取消完成、不能隐藏；它代表原始训练记录。

融合规则在 [能量球与匹配](#能量球与匹配) 中说明。

### 复盘

每个日期可以保存一条复盘：

- 1–5 级：主观疲劳、睡眠质量、肌肉酸痛、心情；
- 训练评分、训练备注、训练日记；
- 自动快照：数据疲劳、当日负荷、CTL、ATL、TSB、ACWR、单调性、训练评价；
- 自动建议与完成数/总数。

复盘按“日”保存，同一天再次保存会覆盖该日记录。

### 教练

- **训练准备度**：5–98 分，综合 HRV、静息心率、TSB、ACWR、睡眠；
- **负荷**：CTL 42 天 EMA、ATL 7 天 EMA、TSB = CTL − ATL；
- **负荷比**：ACWR，7 天 acute / 28 天 chronic；数据不足时按已有天数归一化；
- **单调性与 strain**：7 天负荷均值/标准差，以及周负荷 × 单调性；
- **恢复**：HRV 与基线、静息心率与基线、VO₂max、LTHR、LTSP、stamina；
- **成绩预测**：最近最佳跑步按 Riegel 1.06 外推 5K/10K/半马/全马。

这些指标用于观察趋势，不构成医疗建议。

### 同步

- 区域：中国大陆、国际（美洲）、欧洲；
- 登录：邮箱、手机号、access token；
- `自动同步`：每 10 分钟同步一次；
- `补齐今日`：当天有 COROS 活动时，自动生成一条已完成的今日训练任务；
- 最近活动、匹配状态、手动导入 JSON 入口。

## 能量球与匹配

实际球与计划球融合，不要求属于同一条任务。规则是：

1. 两个球必须属于同一类型（训练/学习/工作/生活/创作/其他）；
2. 再满足任意一项：
   - 同一条任务；
   - 同一种运动；
   - 距离差不超过 20%，且至少允许 0.8 km 误差；
   - 时长差不超过 20%，且至少允许 6 分钟误差；
   - 有相同标签。

融合会保留计划任务，把实际球的训练属性写入计划任务，并将实际球标记为已被吸收。删除计划任务时，服务端会清理指向它的吸收关系，避免留下悬空引用。

## COROS 数据

使用非官方 COROS Training Hub API。连接后读取：

- 活动列表：日期、运动类型、距离、时长、开始/结束时间、平均/最大心率、卡路里、训练负荷、平均/标准化功率、爬升/下降；
- 每日指标：HRV、HRV 基线、静息心率、睡眠评分/时长、训练负荷、负荷比、ATI/CTI、performance、距离、时长、VO₂max、LTHR、LTSP、stamina；
- 活动详情接口未默认逐条拉取，以免触发限流；当前以活动摘要和每日指标为主。

### 已知限制

- 接口不是 COROS 官方公开 API，COROS 更新后可能需要适配；
- 从新设备登录可能使手机 App 的会话失效；
- 睡眠明细需要 COROS 移动端接口和独立 token，本插件默认不读取；每日指标中的睡眠评分如果接口提供则使用；
- COROS、RQrun、rundiag、Stryd、悦跑圈的私有算法不公开，本项目没有复制它们；使用的是公开运动科学模型；
- 成绩预测基于最近最佳跑步，不是赛道实测成绩。

## 数据与隐私

```text
COROS Training Hub
        │  HTTPS（Host 端）
        ▼
lib/coros.js ──► state.json ──► lib/coach.js ──► /rundiag/api/state
        │              │
        │              └── state.json.bak
        └── token 只保存在 Host 端
```

- 数据保存在 DSH profile 的 `rundiag/state.json`，上一版在 `state.json.bak`；
- token 不会出现在 `/rundiag/api/state` 响应中；
- 不发送遥测，不把训练数据上传到第三方；
- `GET /rundiag/api/export` 可导出任务、复盘、活动、每日指标；
- 卸载插件不会自动删除 `state.json`，需要时可手动删除该目录。

## HTTP 接口

Host 端注册在 `/rundiag/api`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/state` | 状态 + 教练计算结果（无 token） |
| POST | `/ops` | 增量操作：任务、完成、排序、合并、复盘、自动同步开关 |
| POST | `/sync` | 立即同步 COROS |
| POST | `/connect` | 邮箱/手机号/Token 连接 |
| POST | `/disconnect` | 断开连接 |
| GET | `/export` | 完整 JSON 导出 |

所有请求由 Host 端鉴权；DSH 0.2.3-alpha 使用 `webServer` 传入的 `peer`，旧版使用 `connection.requestRejection`。

## 更新与卸载

更新：重新执行 `dsh plugin add github:huhu508/dsh-rundiag`，或在 DSH 插件管理里更新，然后刷新页面。

卸载：在 DSH 插件管理中禁用/移除 `dsh-rundiag`。数据目录不会自动删除。

## 故障排除

| 现象 | 处理 |
| --- | --- |
| 右侧栏找不到 rundiag | 确认插件已启用，刷新页面；安装/更新后必须刷新一次 |
| 打开页面提示“无法读取 rundiag 数据” | 确认 DSH 版本 ≥ 0.2.2；0.2.3-alpha 请使用 v0.5.1 及以上 |
| 点击同步没有反应 | 查看浏览器控制台和插件状态；v0.5.3 已修复 `REGION_LABELS` 缺失导致的 SyncView 崩溃 |
| 登录失败 | 确认区域、邮箱/手机号、密码；不要多次尝试触发风控 |
| 同步不到今天的数据 | 检查 `自动同步` 与 `补齐今日`；确认活动日期和运动类型 |
| 能量球消失 | COROS 球不能删除；检查日期是否选对，或关闭再打开面板 |
| 页面样式异常 | 切换主题后刷新；只使用 DSH 主题 token，不写死颜色 |

```text
plugin_manager install_bundle <本目录绝对路径>
```

## 常见问题

**会把我的 COROS 密码上传吗？**

不会。密码只在 Host 端用于换取 access token，不写入 `state.json`，也不会通过 HTTP 返回。插件只持久化 token。

**为什么不直接读取睡眠明细？**

COROS 睡眠明细需要移动端登录体系和另一个短期 token，可能影响手机 App 会话。当前只使用网页接口能提供的每日指标。

**为什么不能取消完成 COROS 生成的任务？**

它们是原始训练记录的投影。删除或取消完成会让能量球与真实数据不一致，因此服务端会强制保持完成状态。

**为什么预测和 COROS App 不一样？**

预测使用公开的 Riegel 模型和最近最佳跑步，不包含 COROS 的私有模型、赛道条件和天气。
